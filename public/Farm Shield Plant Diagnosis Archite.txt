Farm Shield Plant Diagnosis Architecture
We are removing the Supabase Edge Function completely from the plant diagnosis workflow.
New Architecture Flow:

1. User uploads plant image through:

* drag and drop upload OR
* normal image upload option

2. Once uploaded, the image must first be stored in Cloudinary.
Cloudinary will be used only for:

* image storage
* image URL generation
* diagnosis history image persistence
I will provide:

* Cloudinary cloud name 
* upload preset
* API credentials if required

3.convert it to base64 in backend before sending it to plantnet/plant.id -compulsory conversion

4. After image upload is completed successfully in Cloudinary, hit the PlantNet API.
Purpose of PlantNet API:

* identify the uploaded plant accurately
* detect plant species/common name before disease diagnosis
PlantNet API key will be provided.

5. After plant identification is completed, send the same image and identified plant data to Plant.id API.
Plant.id API responsibilities:

* disease identification
* confidence score
* disease classification
* common disease name
* treatment recommendation
* short-term treatment
* long-term prevention
* fertilizer recommendation
* plant health analysis
Plant.id API endpoint and API key will be provided.
Architecture sequence:
User Upload → Cloudinary Storage, then convert to base64 → PlantNet API (plant identification) → Plant.id API (disease diagnosis)
